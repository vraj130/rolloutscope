# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and
this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Isolated wheel-install smoke (`scripts/check_packaging.py`) that builds the package,
  installs it outside the source tree, and checks the CLI, detector entry points, and
  packaged HTML template. CI runs this on Python 3.11, 3.12, and 3.13.
- Frozen lockfile checks (`uv lock --check` and `uv run --frozen`) plus an 85 percent
  coverage floor in `[tool.coverage.report]`.
- Offline performance measurement infrastructure: a deterministic dataset generator
  (`scripts/perf/generate.py`) for small, medium, and large prime-rl-shaped runs, a
  subprocess RSS/runtime recorder (`scripts/perf/measure.py`), and a versioned result
  schema (`scripts/perf/result_schema.json`). This records baselines; it does not
  enforce a resource budget.
- Phase 1 execution manifests, per-file ingestion accounting, per-detector coverage,
  complete verdict JSONL sidecars, and checksum artifact ledgers for report outputs.
- Atomic output staging with source and destination collision detection for analysis and
  conversion outputs.
- One reproducible detector benchmark (`rolloutscope.benchmark`), shared by
  `scripts/trace_validation.py` and the TRACE integration test: a single row mapper, a
  single applicability rule set, a single metric implementation, and a frozen manifest.
  A test runs the script as a subprocess and compares its JSON against the in-process
  report, so the two paths cannot diverge again.
- Frozen TRACE manifest (`benchmarks/trace/manifest.json`) pinning dataset revision
  `31d87f06`, all 517 row ids and labels, a SHA-256 per row, and a per-scenario split
  assignment. Row content is not redistributed: the dataset is gated and CC-BY-SA-4.0.
  Regenerate with `scripts/build_trace_manifest.py`.
- Train, tuning, and holdout splits assigned per scenario rather than per row, from a
  salted hash of the normalized task statement, so assignment does not depend on fetch
  order or size. The holdout is sealed until the detector repairs land.
- Detector applicability accounting: a unit a detector could not evaluate is reported as
  insufficient data with the missing signal named, never as a true negative. On TRACE,
  five of the six detectors report zero coverage instead of a perfect clean record.
- Wilson score intervals on every reported rate, and per-category recall over the TRACE
  taxonomy with inferred category names marked as inferred.
- Hard-negative corpus (`tests/fixtures/hard_negatives/`): 33 cases across all six
  detectors, covering legitimate test maintenance, a user naming dangerous patterns, tool
  output quoting existing code, short-answer tasks, grading-criteria authoring, and
  appropriate repeated agent loops. Each records both the required outcome and the
  measured current one; 21 currently fire, which is the detector-repair backlog.
- Captured upstream artifacts (`tests/fixtures/upstream/`) produced by the real upstream
  writers at pinned versions: verifiers 0.3.1 eval `traces.jsonl`, the legacy prime-rl
  per-step cohort layout, and the current prime-rl chunked stream with its index and
  annotation streams. Generated by `scripts/capture_upstream_fixtures.py`, the only file
  in the repository that imports verifiers, run in a throwaway environment.
- Compatibility research: `docs/compatibility-matrix.md` (which upstream releases write
  which format, and the four ways a current record breaks this reader),
  `docs/upstream-cohorts.md` (the `all` and `effective` cohorts before and after the
  2026-09-01 prime-rl layout change), and `docs/benchmark-metrics.md` (metric
  definitions, split rationale, and reporting format).
- Optional `benchmark` extra (pyarrow) for the revision-pinned parquet fetch path, which
  the public rows API cannot provide. Nothing in the analysis path imports it.

- Opt-in reproducible validation script (scripts/trace_validation.py) that maps
  Patronus TRACE rows into the schema and reports verifier_tamper and
  answer_leakage_echo fire rates on hacked versus clean coding trajectories.
- HF_TOKEN authentication for the TRACE integration test, loaded from a gitignored
  .env through python-dotenv, so the optional network validation can reach the gated
  dataset.

### Changed

- `analyze` and `convert` now discover their input manifest once, reject rollout or
  metadata source collisions before writing, expose an explicit partial-ingestion policy,
  and accept a stable `--run-id` override for legacy raw input.
- Terminal and HTML reports show detector coverage per unit, mode, and run instead of
  combining unlike denominators. Human views cap large tables and evidence with visible
  omission counts while deterministic JSON and verdict JSONL retain the complete data.
- `scripts/trace_validation.py` and `tests/integration/test_trace_dataset.py` no longer
  carry their own row mapping, label parsing, or fire-rate arithmetic. They call the
  shared benchmark library, so they can no longer report different numbers for the same
  dataset. The script now takes `--split` and `--json`, and defaults to the tuning split.
- The TRACE row mapping now produces a multi-turn rollout that keeps assistant-authored
  text out of observed content: simulated tool output becomes role-`tool` context on the
  following step rather than being flattened into the completion. Turn indices and
  tool-call pairing survive.
- README validation section rewritten. It no longer describes TRACE trajectories as real
  (the dataset card says synthetically generated and human verified), no longer quotes
  the previous 85/153 and 73/147 counts, which came from an unpinned and differently
  mapped path, and no longer presents a detector's silence for lack of data as a measured
  clean rate.

### Fixed

- Reports no longer present empty, unsupported, failed, or insufficient analysis as a
  clean "No findings" result.

- degenerate_repetition no longer fires on concatenated multi-turn transcripts (a
  multi_turn rollout, or a completion holding more than one message); repetition is
  measured within a single completion only.

## [0.1.0] - 2026-07-05

### Added

- Project scaffold: uv-managed environment, src layout, CI matrix (3.11 to 3.13),
  placeholder CLI with --version.
- Normalized rollout schema (frozen contract): discriminated union on kind, per-row
  schema_version, extra-key preservation, Verdict and Finding models, content-derived
  IDs with the v1 join contract, streaming JSONL IO with skip-and-log, and a tested
  migration chain.
- ADR-0001 recording the normalized-schema decision and its alternatives.
- Adapters for verifiers eval output (results.jsonl plus metadata.json) and prime-rl
  training rollouts (train_rollouts.jsonl across step directories), with
  auto-detection, content-derived IDs, unknown-key preservation, and step_index
  attached from on-disk layout only.
- Six reward-hacking detectors (verifier_tamper, reward_saturation_group_collapse,
  length_inflation, format_only_wins, degenerate_repetition, answer_leakage_echo)
  with evidence spans, documented false-positive modes, configurable heuristic
  thresholds, entry-point discovery, and labeled hacked/clean fixture pairs.
- Streaming aggregates, verdict-to-finding assembly, and three renderers: rich
  terminal summary, deterministic JSON, and a single-file self-contained HTML report
  with server-side SVG charts.
- Command-line interface (typer): analyze (terminal summary, JSON sidecar,
  self-contained HTML report, --fail-on exit codes), convert (raw artifacts to
  normalized JSONL), detectors list, and schema export, plus TOML config loading over
  the detector, aggregation, and severity settings.
- Synthetic demo run fixture (tests/fixtures/demo) and an end-to-end test suite
  covering the full adapter-to-report pipeline.
- README quickstart, CONTRIBUTING guide with a third-party detector plugin
  walkthrough, and this changelog.
