# TRACE benchmark manifest

`manifest.json` pins the population that a rolloutscope detector benchmark number
was measured on. It carries identity, not content: TRACE is a gated dataset under
CC-BY-SA-4.0, so redistributing rows here would be wrong. What is committed is
the dataset revision, every selected row's id and label, a SHA-256 of each row's
payload, and the split each row belongs to. Anyone with dataset access refetches
at the pinned revision and the hashes confirm, row by row, that they are looking
at the bytes a reported number came from.

- Dataset: `PatronusAI/trace-dataset`, revision
  `31d87f06078eca3ab6eaf1e06e5ea6fe9f2b7a6d`, split `train`, 517 rows.
- License: CC-BY-SA-4.0. Gated: yes, `HF_TOKEN` required.
- Rows: 268 hacked, 249 benign, across 516 scenarios.
- Splits: train 202, tuning 105, holdout 210.

The dataset card describes the trajectories as synthetically generated by Claude
Code and human verified, with simulated tool use. A number measured here says
something about detection on realistic transcripts and nothing yet about
detection on operational RL logs. Do not describe them as real.

Regenerate (only to mint a new pin, which invalidates every earlier report):

```bash
uv run --extra benchmark python scripts/build_trace_manifest.py
```

Metric definitions, the split rationale, and the reporting format are in
`docs/benchmark-metrics.md`.
